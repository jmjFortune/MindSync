# Obsidian NAS Sync 第一版设计

日期：2026-10-12

状态：Docker 架构方向已确认；本文件待用户审阅，尚未开始实现或部署。

## 1. 目标与边界

开发自用 Obsidian 同步插件及配套 NAS 服务。支持 macOS、Windows、Android 手机和 Android 平板。飞牛 NAS 运行一个 Docker 同步服务，第一版直接使用 NAS 本地存储，不实现 WebDAV、网盘、向量数据库或 RAG 查询功能。

每台设备保存完整本地笔记库，可离线编辑。设备无需同时在线，只需分别在同步时访问 NAS。第一版默认在 Obsidian 运行期间同步：启动、回到前台、编辑后及手动触发。Android 关闭应用或被系统挂起后的持续同步不属于第一版承诺；若用户要求此能力，应先扩展设计为独立 Android 服务。

第一版用于一个用户的一份笔记库，多台设备接入。同步 Markdown 和普通附件。默认排除 Obsidian 配置目录、插件自身状态、Git 目录、系统临时文件及符号链接。设置和插件跨平台同步、多人协作编辑、网页编辑器、端到端加密、NAS 文件夹外部编辑自动导入均留到后续。

## 2. 架构

```text
Obsidian 插件（macOS / Windows / Android）
  本地文件操作 → 持久化离线队列 → 同步调度 → HTTP API
                                             ↕
飞牛 Docker 服务
  身份认证 → 版本检查 → 事务化元数据与变更日志
                         ↕
                  NAS 本地内容存储

未来：存储适配器接 WebDAV / 网盘；内容与变更 API 接 RAG 消费者。
```

插件使用 TypeScript 和 Obsidian 跨平台 API，不依赖桌面专属的 Node 文件系统或 Electron API。网络请求使用 Obsidian requestUrl；笔记与附件操作使用 Vault API，私有状态通过插件数据目录的 Adapter API 保存。

服务使用 Python、FastAPI、SQLite 和本地文件存储。第一版只运行一个服务实例。SQLite 位于飞牛本地磁盘的 Docker 挂载目录，由服务独占访问，不放在 SMB、NFS 或 WebDAV 挂载上。

## 3. 服务端数据与文件

持久化目录约定为 `/data`，下设：

- `metadata/`：SQLite 数据库，保存文件身份、版本、操作结果、设备、变更游标和删除记录。
- `objects/`：按 SHA-256 标识的不可变内容，保留历史版本引用的对象。
- `vault/`：最新笔记及附件的可读文件树，供查看与导出。
- `tmp/`：未完成的上传临时文件。

权威数据是数据库已提交的版本及其不可变对象；可读文件树是可重建的投影，避免数据库事务与文件覆盖之间的崩溃窗口造成丢失。更新顺序为：写临时内容、校验大小及哈希、持久化并原子移入对象存储、数据库提交版本和变更记录、更新可读文件树。仅在权威版本已提交后向客户端返回成功。崩溃后启动时修复投影；缺失权威对象时报告故障，不以空文件替代。

第一版不自动清理历史对象及删除记录，避免长期离线设备复活已删除文件。展示存储使用量，历史保留与垃圾回收作为后续独立功能。同步不是备份；恢复方案同时保留元数据和内容对象。

NAS 上的可读文件树只供查看和导出。直接修改它不会被自动同步，界面与部署文档必须说明。未来 RAG 通过内容 API 读取权威版本，而非监听这个投影目录。

## 4. 同步协议

每份笔记库有稳定的 vault ID，每个文件有稳定的 file ID。文件版本为服务端分配的递增 revision；笔记库变更日志有递增 cursor，不依赖各设备系统时间。插件保存每个文件的上次确认版本、内容哈希和待提交操作。

客户端首先获取远端变更，结合本地修改及基线形成计划；在写入本地前再次核对文件当前内容，避免覆盖同步期间的用户编辑。上传、重命名、删除均携带 baseRevision 和唯一 operation ID。

服务端在同一数据库事务内检查 baseRevision、路径唯一性、提交新版本及追加变更记录。重复提交相同 operation ID 返回原结果，不重复创建版本；同一 ID 携带不同请求内容时拒绝。读取变更包含明确的分页边界和上界游标，客户端仅在该页内容处理完毕并持久化后前移游标。

离线队列采用可恢复的原子状态写入。断网、超时、客户端重启和服务重启后允许重试。上传确认丢失时通过 operation ID 恢复结果，不根据超时判断上传失败。远端变更写入本地所触发的 Obsidian 事件必须通过已确认内容哈希识别，避免反馈循环。

不启用纯时间戳“最后写入者覆盖”。初次连接非空本地库和非空远端库时先给出合并预览：相同内容建立关联，不同内容生成冲突副本；没有基线不推断删除。

## 5. 冲突、删除与重命名

第一版采用严格版本检查，不做自动文本合并。版本不匹配返回结构化冲突信息，原远端版本保持不变。插件将本地候选内容持久化为带设备标识及唯一后缀的普通冲突副本，再按正常创建流程同步，使其他设备也能看到。原文件获取远端当前版本前，必须确认本地候选已持久化。状态界面显示冲突文件及来源，并提供“打开两份内容”命令。

编辑与删除同时发生时保留编辑内容为冲突副本；拒绝过期删除，避免旧设备删除较新内容。远端删除通过持久化 tombstone 传播，不根据一次目录扫描中的文件缺失推断删除。

重命名保持 file ID，作为版本操作提交。目录重命名按文件展开，执行期间可恢复，不承诺跨全部文件的原子操作。目标路径被占用时报告冲突，不能覆盖已有文件。

路径采用跨平台规范：相对路径、统一分隔符及 Unicode 规范化，拒绝绝对路径、`..`、Windows 保留名和不合法字符。比较路径时检测大小写等价冲突，不允许 Linux 服务端创建 Windows 无法区分的两份文件。大小写重命名在需要时通过临时路径完成。禁止路径逃逸和跟随存储根目录中的符号链接。

## 6. 附件与同步调度

笔记与附件使用同一版本协议。传输后校验 SHA-256，失败时不提交版本。已有相同哈希对象可复用。第一版采用有大小上限的单文件传输，不实现分片续传；默认单文件上限 50 MiB，可由服务端配置，客户端读取服务端能力并显示超限文件。超限不得静默跳过。

前台同步默认每 5 秒检查远端变更，本地编辑停止约 1 秒后触发同步；同一客户端同一时间只运行一个同步任务。网络失败按指数退避并加入随机偏移，重新回到前台时主动恢复。首次扫描与重启后的扫描补足应用未运行期间的变更。

界面包括：服务器地址、设备名称、令牌、连接测试、同步预览、手动同步、暂停同步、当前状态、待同步数量、最后成功时间和明确的错误信息。认证失败要求更新凭证，不能无限重试；冲突不阻塞无关文件。

## 7. API 边界

第一版提供版本化 HTTP API，协议独立于文件存储布局：

- 健康及能力查询：协议版本、文件大小上限等。
- 设备与凭证：设备注册、令牌撤销。
- 文件清单快照及分页变更读取。
- 不可变内容上传和按版本下载。
- 文件创建、更新、重命名、删除及 operation ID 结果查询。
- 指定版本恢复：在当前基线上创建新版本，而非回退日志游标。

详细 JSON schema 和端点命名在实现计划中制定，必须先于客户端、服务端并行实现。错误包含稳定错误码与可读说明，不向客户端暴露服务器内部路径、凭证或堆栈。

## 8. 部署与认证

交付 Dockerfile、Docker Compose 示例及飞牛部署说明。服务端口和数据目录可配置，容器重启保留全部数据，健康检查区分进程存活与存储可用。升级前保留可恢复备份，数据库 schema 迁移具有版本记录。

服务采用每设备可撤销令牌，服务端只保存令牌哈希；初始化凭证不得硬编码进镜像或仓库。日志不记录令牌和笔记正文。插件凭证仅保存在本地插件配置中，默认不参与同步。

先验收局域网同步，再验收外网。Docker 部署不会自动使服务可从互联网访问；外网方案取决于现有网络通道，不能假定 FN Connect 能代理任意 Docker 服务。远程连接使用有效证书的 HTTPS，不通过忽略证书校验解决连接问题。没有外网入口时仍交付可用的局域网版本，并明确外网未验收。

备份通过服务的备份流程或停服后复制完整数据目录完成，不能在活跃 SQLite WAL 写入时仅复制 `.db` 文件。

## 9. 后续扩展边界

存储接口围绕不可变对象读取、写入、存在性检查及能力声明设计，第一版仅实现本地存储。未来增加 WebDAV、S3 或网盘时，同步协议、版本元数据和冲突规则保持一致；这些存储后端由 NAS 服务调用，不要求每个 Obsidian 客户端重写同步引擎。

“插件脱离 NAS、直接连接网盘”是另一种架构，当前不承诺。如果后续要求，应单独设计元数据一致性与认证。

RAG 复用权威内容读取和持久化变更游标。索引消费者持久化自己的处理游标，按版本幂等更新，消费删除与重命名；索引失败不阻塞笔记同步。第一版不调用外部模型或上传笔记到第三方。未来加入端到端加密时，需重新明确 NAS 上 RAG 的解密授权。

## 10. 验收

- 两台电脑和 Android 两类设备之间双向同步笔记及附件；无法获取实机时分别报告模拟验证和待完成实机验证，不把构建成功当成跨平台验收。
- 离线修改、断网重连、重启、上传成功但响应丢失，均不会造成内容丢失或重复版本。
- 双端并发编辑、编辑与删除、目标路径占用、大小写路径冲突，均保留候选内容并明确报告。
- 已删除文件不会因长期离线设备上线而恢复；无基线设备不会将远端误判为批量删除。
- 分页同步和中途退出不会跳过变更；同步期间的新本地编辑不会被下载覆盖。
- 损坏内容、非法路径、撤销凭证、超限附件和 NAS 磁盘写入失败均得到明确处理。
- Docker 数据目录持久化、崩溃后投影修复、备份恢复及版本恢复经过实际验证。
- 对同步状态机和故障场景编写有意义的集成测试；构建插件、验证 Compose 配置并启动容器。平台和外网测试结果分开报告。
